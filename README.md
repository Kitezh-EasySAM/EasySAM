# EasySAM

Прототип системы учёта программного обеспечения и лицензий (Software Asset Management) — кейс хакатона СургутАСУнефть.

Что делает:

- ведёт каталог разрешённого ПО: тип лицензии, раздел реестра российского ПО, внутренний статус (актуальное, устаревшее, запрещённое);
- собирает установленное ПО с компьютеров: агент для Windows, файл выгрузки (CSV/XLSX) или ручной ввод;
- очищает «грязные» данные: отсекает служебные компоненты, сопоставляет названия с каталогом, остаток показывает во вкладке каталога «Нераспределённое» с подсказками;
- считает «куплено / установлено» и показывает риски в рублях: нехватка лицензий, простой, неиспользуемые установки, запрещённое ПО и факт его запуска;
- ИИ: проверка лицензионного соглашения по ссылке или тексту, подсказки сопоставления названий, ассистент с вопросами на русском языке. Без подключённой модели всё, кроме подсказок сопоставления, работает на правилах.

## Запуск в Docker

```bash
docker compose up -d --build
```

Интерфейс и API: http://localhost:8000, агент для Windows — http://localhost:8000/downloads/sam-agent.exe (собирается внутри образа; без него сборка быстрее: `AGENT=0 docker compose up -d --build`). Вход `admin` / `admin` — при первом входе система попросит сменить пароль. База — в томе `sam-data`.

При первом старте в пустую базу записывается стартовый каталог (корпоративные продукты и типы лицензий). Компьютеры появятся, когда подключатся агенты или будет загружен файл выгрузки (см. ниже).

Адрес, по которому компьютеры видят сервер, задаётся в `.env` рядом с `docker-compose.yml` — он попадёт в `sam-agent.json`:

```
PUBLIC_URL=http://192.168.1.10:8000
```

Без него в `sam-agent.json` попадёт адрес из браузера, и если интерфейс открыт на `localhost`, компьютеры сервер не найдут.

API поднимется на `:8000`, интерфейс — на http://localhost:5173. Настройки — в `.env` (образец: `.env.example`).

## Подключение компьютеров

«Рабочие места» → вкладка «Установка агента»: скачать `sam-agent.exe`, скачать `sam-agent.json` (в нём адрес сервера и новый ключ регистрации), положить оба файла в одну папку на ПК и запустить exe от имени администратора. Подробности — `agent/README.md`.

Без агента: «Настройки» → «Установки на ПК» — загрузка файла выгрузки или ввод одной установки вручную.

## ИИ

В `.env` задаётся любой OpenAI-совместимый адрес, например локальная модель в LM Studio:

```
OPENAI_BASE_URL=http://localhost:1234/v1
LLM_MODEL=qwen/qwen3.5-9b
```

В модель уходят только названия программ и тексты лицензий, данные о людях — нет.

## Архитектура

```
Агент (Windows-служба, agent/)                     Сервер (server/)
 программы, лицензии, процессы  ───────────────►  /api/ingest/*   (снимок, изменения, запуски)
 задания (только ключ КриптоПро, снимок) ◄──────  /api/agent/commands
Интерфейс (web/) ◄── REST /api/* + живая лента SSE /api/stream ◄── services/* ◄── SQLite
Файл CSV/XLSX из интерфейса ───────────────────►  /api/ingest/csv (тот же конвейер, что у агента)
```

| Папка | Что внутри |
|---|---|
| `server/` | API: Node.js 26, TypeScript без сборки, Fastify, Zod, встроенный SQLite. Логика — в `src/services/` (чистые функции и запросы), маршруты `src/routes/` тонкие, доступ проверяется в одном месте — `src/routes/auth.ts` |
| `web/` | интерфейс: Vite, React. Страницы — `src/pages/`, общие элементы — `src/components/ui/`, обращение к API — `src/api/` |
| `agent/` | агент для Windows на Rust: служба, сбор, задания. Что собирает и что отправляет — `agent/README.md` |
| `docs/` | `API.md` — контракт API, `DATA_MODEL.md` — таблицы и инварианты, `LICENSES_RU.md` — откуда берутся ключи российского ПО |

## Проверка качества

```bash
make check
```

Одна команда — то же, что CI (`.github/workflows/ci.yml`). Нужны Node.js 26, Rust stable с целью `x86_64-pc-windows-gnu` и `mingw-w64-gcc`. Перед первым запуском — `npm install` в корне и в `web/`: форматирование (Prettier, rustfmt), линтер ESLint без предупреждений, типы, тесты сервера (`node --test`), юнит-тесты фронта (Vitest), сборка фронта, тесты агента и clippy агента для Linux и Windows без предупреждений.

```bash
make e2e
```

Обход интерфейса в браузере (Playwright, нужен Chrome: `cd web && npx playwright install chrome`): свой сервер на `:8190` с временной демо-базой — поэтому нужны файлы в `материалы/`; все экраны на ширине 1440 и 400 px без ошибок и горизонтальной прокрутки, старые адреса, сценарии (фильтры, дубли, окна, удаление, роль «просмотр»).

```bash
make format
```

## Безопасность

- **Вход и роли.** Пароли — scrypt с солью; сессия — HttpOnly-cookie `SameSite=Strict`, в базе только хеш токена. Роль «просмотр» только читает (и спрашивает ассистента). Выданный пароль (первый `admin`, созданный или сброшенный администратором) нужно сменить при первом входе — до этого доступна только смена пароля. Перебор: блок после 5 неудач по паре «логин + IP» и 30 — с одного IP.
- **Агенты.** Каждый ПК получает собственный токен по ключу регистрации (ключ — в `sam-agent.json`, который скачивается в интерфейсе); токен принимается только для своего серийного номера. Общий токен выключен, пока не задан `INGEST_TOKEN`. Агент выполняет только задания из белого списка.
- **Секреты.** С ПК приходят только 5 последних символов ключей лицензий; полный ключ из хранилища уходит только агенту-адресату. Ключи регистрации и токены хранятся хешами. `/downloads/` отдаёт только `*.exe` и `*.ps1`.
- **Веб.** CSP и `X-Frame-Options`, `nosniff`, `Referrer-Policy` у страниц и API; изменяющие запросы с чужого сайта отклоняются (проверка Origin вдобавок к SameSite); поиск экранирует `%` и `_`.
- **ИИ.** В модель уходят только названия программ и тексты лицензий. SQL от модели — только один `SELECT` по белому списку таблиц, в отдельном процессе на соединении только для чтения, с лимитом строк и времени; запрос показывается пользователю. Загрузка страниц лицензий не ходит во внутреннюю сеть (проверка адреса при каждом соединении).
- **Зависимости.** `npm audit` сервера — 0 уязвимостей (`uuid` закреплён через `overrides`).

## Данные

Файлы организаторов хакатона (выгрузка установленного ПО с ПК, перечень разрешённого ПО, справочник лицензий) в репозиторий не входят. Если они у вас есть — создайте в корне папку `материалы/`, положите туда `.xlsx` (тип файла определяется по шапке, имена любые) и наполните пустую базу:

```bash
make fresh
```

Без файлов `make fresh` создаёт только стартовый каталог; Docker всегда стартует так — данные в нём загружаются через интерфейс. Демо-данные (закупки, цены, сотрудники, лицензии с ПК, ключи КриптоПро — их в материалах нет) добавляются к компьютерам из выгрузки: `make demo` или `make fresh-demo`, в Docker — после загрузки выгрузки через интерфейс: `docker compose exec sam node src/scripts/run-demo.ts`. Без выгрузки демо пропускается. В интерфейсе соглашения демо-данных подписаны «(демо)».

Свою выгрузку можно загрузить и без этого — «Настройки» → «Установки на ПК», CSV/XLSX с колонками `SERIAL_NUMBER, DISPLAYNAME, PUBLISHER, VERSION`.

## Ограничения прототипа

- Обмен по HTTP: для реальной сети сервер нужно поставить за прокси с TLS (`COOKIE_SECURE=1`, `TRUST_PROXY=1`).
- Ключи лицензий в хранилище лежат в базе в открытом виде; наружу отдаётся только маска.
- Учёт лицензий — по числу устройств; лицензии на пользователя и конкурентные не моделируются.
